# GifForge — GIF Maker

**Live:** https://spongebobsquare22.github.io/gif-tool/

A free GIF maker for image frames. It runs entirely in the browser (no uploads, no server, no build step) and is hosted on GitHub Pages. Optional Windows PowerShell scripts are included if you'd rather batch-process frames locally.

![Static site](https://img.shields.io/badge/hosting-GitHub%20Pages-ff5c8a) ![No build step](https://img.shields.io/badge/build-none-5cc8ff) ![100% client-side](https://img.shields.io/badge/privacy-100%25%20local-a78bfa)

## The website

**`index.html`** is the GIF maker. Drop in **as many images as you want** — 2 frames or 300 — and they all become one animated `.gif`. Reorder them, set the timing, and download.

> It is not a one-image converter. Every image you add becomes a frame of the same animation, in the order you choose.

### Features

- Batch upload: drag in a whole folder/selection of images at once, or pick them with the file browser
- Up to **300 frames** per GIF, all merged into a single animation
- Accepts PNG, JPG, WebP, GIF, and BMP — mixes fine in one project
- Files are naturally sorted by name (`frame2.png` before `frame10.png`), so numbered sequences land in the right order
- Thumbnail grid with drag-to-reorder, arrow nudge buttons, remove, and reverse
- Live animated preview with play/pause and frame scrubbing
- Frame delay / FPS presets (30, 24, 15, 10 fps)
- Loop count, max width, color count (256 → 32), and background color
- **Transparent GIF output** — semi-transparent pixels are binarized at alpha ≥ 200, which removes the fuzzy edge noise and white bleed that GIF encoders produce from soft PNG alpha
- Encoding runs in a Web Worker, so the UI stays responsive
- Everything is local: images never leave the browser

### Run it locally

Browsers block ES modules and module workers on `file://`, so use any tiny static server from the project folder:

```powershell
# Python (already installed on most systems)
python -m http.server 8000

# or Node
npx serve .
```

Then open <http://localhost:8000>.

### Publish on GitHub Pages

1. Create a repository on GitHub and push this folder to the `main` branch.
2. In the repo, open **Settings → Pages**.
3. Under **Build and deployment**, choose **Deploy from a branch**.
4. Select branch **main** and folder **/ (root)**, then save.
5. Your site appears at `https://spongebobsquare22.github.io/gif-tool/` in a minute or two.

No build, no Actions workflow, and no server code are required. The included `.nojekyll` file tells GitHub Pages to serve the files as-is.

#### What gets uploaded

`.gitignore` keeps the published repo small. These are excluded from the repo:

| Ignored | Size | Why |
|---------|------|-----|
| `gifski-cli/` | ~55 MB | Local CLI binary; the website doesn't use it |
| `frames-clean/` | ~1.2 MB | Generated by `clean-frames.ps1` |
| `output*.gif` | ~200 KB each | Generated GIFs |

The site itself needs only `index.html`, `assets/`, `vendor/`, `frames/` (the 16 demo frames), `gif-guide.html`, and the `.ps1`/`.bat` scripts — roughly 2 MB total.

```powershell
git init
git add .
git commit -m "GIF maker site"
git branch -M main
git remote add origin https://github.com/<you>/<repo>.git
git push -u origin main
```

`git add .` respects `.gitignore`, so the 55 MB CLI folder is skipped automatically. To include it, remove the `gifski-cli/` entry from `.gitignore` (GitHub warns above 50 MB per file and blocks above 100 MB).

### Notes on GIF transparency

GIF supports only **1-bit transparency** — a pixel is either fully visible or fully invisible. The worker thresholds the source alpha at 200/255, so:

- Solid sprite pixels stay opaque
- Anti-aliased fringes become transparent instead of turning into white or noisy halos
- No semi-transparent dithering noise is left behind

If you want a solid backdrop instead, pick Black, White, Dark, or a custom color under **Background**. This is often the cleanest option for sprites that were originally drawn against a solid color.

## Optional: Windows CLI pipeline

The repo also contains a local, higher-quality batch pipeline built around the free **gifski** CLI. It is handy for exporting many frames at full resolution without opening a browser.

### Requirements

- Windows PowerShell 5.1+ (or PowerShell 7)
- The gifski CLI at `gifski-cli\win\gifski.exe` (v1.32.0) — included locally, but **excluded from the published repo** by `.gitignore` to keep it small. After a fresh clone, grab the CLI zip from <https://gif.ski/> and extract it into `gifski-cli\win\`.
- No FFmpeg install needed for the clean pipeline

If PowerShell blocks local scripts, allow them for the current user:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

### Make a GIF

```powershell
# Simple: frames/ -> output.gif (full 531×650 resolution)
.\make-gif.ps1

# Clean: binarize alpha -> frames-clean/ -> output-clean.gif
.\make-clean-gif.ps1
```

Or double-click **`make-gif.bat`** in Explorer.

### Scripts

| Script | What it does |
|--------|--------------|
| `make-gif.ps1` | Encodes `frames\*.png` → `output.gif` with the bundled gifski CLI |
| `make-gif.bat` | Double-click wrapper for the simple pipeline |
| `clean-frames.ps1` | Thresholds alpha (≥ 200 → opaque, else transparent) into `frames-clean\` |
| `make-clean-gif.ps1` | Runs `clean-frames.ps1`, then encodes `frames-clean\` → `output-clean.gif` |
| `renumber.ps1` | Renames arbitrary PNGs to `frame0001.png`, `frame0002.png`, … |

### Speed (FPS)

Edit `$Fps` at the top of `make-gif.ps1` or `make-clean-gif.ps1`:

```powershell
$Fps = 12   # slower
$Fps = 24   # faster
```

Or call the CLI directly:

```powershell
.\gifski-cli\win\gifski.exe --fps 24 -o .\output-clean.gif .\frames-clean\*.png
```

For 16 frames: 8 fps ≈ 2.0 s, 12 fps ≈ 1.3 s, 24 fps ≈ 0.67 s, 30 fps ≈ 0.53 s.

> Keep GIF playback at 50 fps or below — browsers clamp higher rates, and gifski may drop frames that can't be represented by GIF's 10 ms delay granularity.

### Troubleshooting

- **`GDI+` error in `clean-frames.ps1`** — already fixed by saving through a `MemoryStream` and using absolute paths. If you edit the script, keep both.
- **GIF has extra/less motion than expected** — adjust `$Fps`; avoid very high values like 60.
- **White fringe around the sprite** — use `make-clean-gif.ps1` (binary alpha) or pick a solid background in the web app.
- **Wrong frame order** — run `renumber.ps1`, or drag the thumbnails in the web app.
- **`winget install gifski` gives a GUI app** — that build is not the CLI. Download the CLI from <https://gif.ski/> and extract it into `gifski-cli\win\` (it is not part of this repo).

For a fuller walkthrough, open **`gif-guide.html`** in a browser.
